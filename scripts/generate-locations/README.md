# Offline country and city data

Run `node scripts/generate-locations/generate.cjs /path/to/cities15000.txt`. The checked-in JSON is bundled by Metro and requires no network on a device. The country list was extracted from the IANA tzdb ISO 3166-1 table (249 entries), with English names generated using Node.js 24.22.0, ICU 78.3 / CLDR 48.0. `countries.json` is the pinned snapshot; regenerating cities never consults the runtime's Intl data. Source city input supplied by the user had SHA-256 `b38089d2cdda494371a4ecef2ddbe4879f2a6688a753d17a1f81cdd4b2a833c4`. The generated snapshot contains 34,194 records; 21 input rows outside the ISO list or invalid were rejected. This source is not all settlements or all capitals. GeoNames changes to names, coordinates and time zones require rebuilding the bundled data. Operating-system timezone rules are also updated independently by Android.

Changes: filtered to the pinned ISO countries, reduced fields, sorted and converted to JSON. Unicode CLDR: © Unicode, Inc., Unicode License V3, https://www.unicode.org/license.txt. IANA time zone database: https://www.iana.org/time-zones.

Indian admin1 codes are mapped to the app's Indian state IDs in `src/data/cities/index.ts`, based on GeoNames `admin1CodesASCII.txt`: https://download.geonames.org/export/dump/admin1CodesASCII.txt. Unknown codes deliberately leave the state and regional festival rule unspecified. The mapping must be reviewed when updating the location dataset.
